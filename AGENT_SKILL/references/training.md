# Training and Weight Export

Sources: `train_AGENT/2d/train_AGENT2d.jl` and `train_AGENT/3d/train_AGENT3d.jl` in the analysis repository. Both start from random initialization without reading or overwriting released weights. The current data and recipe alone do not prove that the released checkpoints were generated by these exact scripts and inputs; exact reproduction requires training logs and provenance.

## File layout and recipe

All inputs are headerless, whitespace-delimited numerical matrices. PGF files with `.csv` extensions are actually tab-delimited.

| Property | 2D | 3D |
|---|---|---|
| Parameter file | `2d/ps_for_train.txt`, 2807×4 | `3d/ps_for_train.txt`, 2751×6 |
| Reduced PGF | `2d/matrix_Gz1.csv`, 7×2807 | `3d/matrix_Gz1.csv`, 7×2751 |
| Full PGF | `2d/matrix_Gz1z2.csv`, 49×2807 | `3d/matrix_Gz1z2z3.csv`, 343×2751 |
| Concatenated input | 8×2807 | 10×2751 |
| Default initialization seed | 20260916 | 20260913 |
| Training precision | Float64 | Float64 |
| Adam updates | 2000 | 3350 |
| Learning rate | 0.03×0.1^((t−1)/1999) | 0.03×0.1^((t−1)/3349) |
| Maximum L-BFGS updates | 12000 | 21000 |
| L-BFGS history | 30 | 30 |

The scripts and README state that SSA targets use 10000 trajectories. The repositories do not contain a dedicated generator for all training targets or the raw trajectories for every group. Treat this as a provenance statement, not as regeneration verified during skill creation.

Parameter row i, reduced-PGF column i, and full-PGF column i represent the same group. Input assembly is `vcat(reduced,permutedims(truth[:,4:end]))`; the first three kinetic parameters enter through the reduced PGF rather than being concatenated directly.

`training_data()` checks exact dimensions, finite inputs/targets, truth>0, and targets in [0,1+1e-12]. It does not perform every possible physical PGF check or automatically check training/inference overlap. In the inspected snapshot, neither complete four- nor six-parameter training vectors overlap their corresponding 400-row inference-truth tables exactly or within an absolute difference of 1e-12 in every coordinate. Recheck after data changes.

## Standardization, loss, and optimization

Training computes μ and sample standard deviation per input row, with a scale floor of 1e-12, and uses `X=(input.-mu)./scale`.

The full-batch loss is `sum(W .* (sigmoid(core(X))-target).^2)/N`, with tensor-product quadrature weights appropriate to the dimension. All samples enter training together; there is no built-in training/validation split or minibatching.

Adam retains one optimizer state throughout the decay stage while updating the learning rate. L-BFGS uses `Optim.only_fg!`, Flux.pullback, and `m=30`, with g_tol/x_tol/f_tol all zero. The iteration limit is not a completion guarantee: line search can terminate early. The trace records actual updates.

Changing adam_steps shortens the stage without changing the learning-rate formula's denominator. A short smoke run therefore does not complete the full decay from 0.03 to 0.003.

## Export

Fold standardization into the first layer:

```julia
folded_W = core[1].weight ./ permutedims(scale)
folded_b = core[1].bias .- folded_W * mu
```

Export folded weights in the same order as `Flux.destructure`. The script checks that pre-sigmoid outputs for the first five samples agree between raw-input/folded and standardized-input/original models, with rtol/atol=1e-10. Subsequent inference uses raw inputs.

The default output is `outputs/` under the corresponding training directory. The script errors if that path already exists to prevent overwriting; choose a new output path. Each run writes:

- `params_trained2d.txt` or `params_trained3d.txt`: single-column params CSV, exported as Float64.
- `training_trace.csv`: stage, update, loss, and learning_rate; L-BFGS learning_rate is NaN.
- `training_summary.toml`: seed, group count, Adam updates, requested/actual L-BFGS updates, history, training_seconds, final_loss, folded flag, and precision.

training_seconds covers only the Adam and L-BFGS stages, excluding data loading, initialization, folding, and export. Training returns parameters, trace, and final_loss.

## Execution

Run separately within the analysis project environment:

```sh
julia --project=. train_AGENT/2d/train_AGENT2d.jl
julia --project=. train_AGENT/3d/train_AGENT3d.jl
```

For interactive use, include one script and explicitly call `train()`; inclusion alone does not start training. The scripts define identically named constants and functions, so use separate processes.

When only the training pipeline needs verification, call `train(output=...,adam_steps=1,lbfgs_steps=1)` with a new temporary output directory. This is a short check, not a full training result. Before retraining, establish the output location, computation scope, and comparison metrics.

## Data or model changes

Before changing a training set, preserve the original data or a traceable version and selection indices. Update parameter rows and PGF columns together and maintain separation from inference truth. Changes to n, width, input features, output ordering, or precision also require corresponding loader and target-grid changes, not merely one edited constant.

Evaluate new weights using both PGF fit and parameter recovery over the requested groups, retaining raw errors and failures. Label model selection based on those same groups as tuning. Do not guide individual fits with inference truth and still describe them as blind inference.
